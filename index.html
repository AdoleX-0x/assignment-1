How the Web Works: A Journey from URL to Screen

By Daniel Ejeh

Sep 13, 2026 · 5 min read

Every day, billions of people type a web address into a browser, tap a link, or ask a search engine a question and in a fraction of a second, a page appears. It feels instant and almost magical. But underneath that simplicity is a carefully engineered system of protocols, servers, and standards that have been refined over more than three decades. This article breaks down what actually happens when you use the web, piece by piece.

1. The Web vs. the Internet

Before going further, it helps to separate two terms people often use interchangeably.

  • The Internet is the physical and logical infrastructure, a global network of interconnected computers, routers, and cables (including undersea fiber-optic lines) that can exchange data.
  • The Web (World Wide Web) is a service that runs on top of the internet. It’s a system of linked documents and resources, accessed using web browsers, identified by URLs, and delivered mainly through the HTTP/HTTPS protocol.

The internet also carries other services like email, file transfer, video calls but the web is by far the most visible one to everyday users.

2. It Starts with an Address: The URL

Everything begins with a URL (Uniform Resource Locator), such as:

https://www.example.com/articles/how-the-web-works

This string is broken into parts the browser understands:

  • Scheme (https://) — tells the browser which protocol to use.
  • Domain name (www.example.com) — the human-readable address of the server.
  • Path (/articles/how-the-web-works) — the specific resource being requested on that server.

Humans read domain names, but computers route traffic using numerical IP addresses. This is where the next step comes in.

3. DNS: The Internet’s Phonebook

To convert www.example.com into something like 93.184.216.34, the browser consults the Domain Name System (DNS).

The lookup typically follows this path:

  1. The browser checks its own cache, has it looked this up recently?
  2. If not, it asks the operating system, which may also have a cached answer.
  3. If still unresolved, the query goes to a DNS resolver (often run by your ISP or a public service).
  4. The resolver queries a hierarchy of DNS servers starting with root servers, then top-level domain (TLD) servers (like those managing .com), and finally the authoritative name server for that specific domain until it finds the IP address.

This entire process usually takes only milliseconds, and the result is cached at multiple levels so it doesn’t need to be repeated for every request.

4. Establishing a Connection

With an IP address in hand, the browser needs to establish a reliable connection to the server.

  • TCP handshake: Most web traffic runs over TCP (Transmission Control Protocol), which starts with a three-way handshake (SYN, SYN-ACK, ACK) to establish a stable, ordered connection between client and server.
  • TLS handshake (for HTTPS): If the site uses HTTPS — which is now the vast majority of the web — an additional TLS (Transport Layer Security) handshake happens. This negotiates encryption keys and verifies the server’s identity using a digital certificate, ensuring the data exchanged can’t be easily intercepted or tampered with.

Newer protocols like QUIC (used by HTTP/3) combine these steps and run over UDP instead of TCP, reducing the number of round trips needed and speeding up connection setup — especially valuable on mobile networks.

5. The HTTP Request

Once connected, the browser sends an HTTP request to the server. A simplified version looks like this:

GET /articles/how-the-web-works HTTP/1.1
Host: www.example.com
User-Agent: Mozilla/5.0 ...
Accept: text/html

This request includes:

  • A method (GET to retrieve data, POST to submit data, etc.)
  • Headers with metadata (browser type, accepted formats, cookies, authentication tokens)
  • Sometimes a body, if sending data such as a form submission

6. What Happens on the Server

The server receiving this request isn’t just a passive file cabinet. Depending on the site, it might:

  • Serve a static file directly (an HTML page, image, or stylesheet)
  • Run application code (in languages like Python, JavaScript/Node.js, PHP, Java, or Go) to generate a page dynamically
  • Query a database to fetch content — user profiles, product listings, articles
  • Call other internal services or APIs
  • Apply authentication and authorization checks

Many popular sites don’t rely on a single server at all. They use load balancers to distribute traffic across many servers, and content delivery networks (CDNs) to serve static content (images, videos, scripts) from locations physically closer to the user, reducing latency.

7. The HTTP Response

Once processed, the server sends back an HTTP response:

HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 5824

<!DOCTYPE html>
<html>...</html>

Key parts include:

  • A status code (200 for success, 404 for not found, 500 for server error, 301 for redirect, and many others)
  • Headers describing the content type, caching rules, and cookies
  • The body — typically HTML, but could be JSON, an image, or other data

8. Rendering: Turning Code into a Page

This is where the browser does its heavy lifting. The process generally follows these stages:

  1. Parsing HTML — the browser reads the HTML and builds the DOM (Document Object Model), a tree-like structure representing the page’s elements.
  2. Parsing CSS — stylesheets are parsed into the CSSOM (CSS Object Model), describing how each element should look.
  3. Combining into a render tree — the DOM and CSSOM are merged to determine what’s actually visible and how it’s styled.
  4. Layout (reflow) — the browser calculates the exact size and position of every element on the page.
  5. Paint — pixels are drawn to the screen based on that layout.
  6. JavaScript execution — scripts may run at various points, modifying the DOM, fetching additional data, or responding to user interaction. This can trigger the layout and paint steps to repeat.

Modern pages often fetch additional resources during this process — images, fonts, further scripts, or data from APIs — each requiring its own request-response cycle, though browsers parallelize many of these for speed.

9. Interactivity and the Modern Web

Early web pages were mostly static documents. Today, much of the web behaves more like software:

  • JavaScript frameworks (React, Vue, Angular, Svelte, and others) let developers build highly interactive interfaces.
  • APIs (often using REST or GraphQL) allow the browser to fetch data without reloading the whole page — this is the basis of AJAX and single-page applications (SPAs).
  • WebSockets enable persistent, two-way connections for real-time features like chat apps or live notifications.
  • Service workers and caching strategies allow web apps to work offline or load near-instantly on repeat visits.

10. The Invisible Standards Holding It Together

None of this works without agreed-upon rules. Organizations like the W3C (World Wide Web Consortium) and the IETF (Internet Engineering Task Force) maintain the standards for HTML, CSS, HTTP, and related technologies, ensuring that a page built by one developer, using one browser, renders consistently for users everywhere on different devices and browsers.

Putting It All Together

To recap the full journey from typing a URL to seeing a rendered page:

  1. You enter a URL or click a link.
  2. The browser resolves the domain name to an IP address via DNS.
  3. A connection is established (TCP, then TLS for HTTPS).
  4. The browser sends an HTTP request to the server.
  5. The server processes the request — possibly querying a database or running application logic — and sends back a response.
  6. The browser parses the HTML/CSS, builds the DOM and CSSOM, and renders the page.
  7. JavaScript runs, enabling interactivity and additional data fetching.

All of this typically happens in under a second. What feels like a single, seamless action is actually a relay of dozens of small, precise steps across a global network — a system built collaboratively over decades that now underpins how the world communicates, works, shops, and learns.
